# UI Architecture Audit: Github-direct

## 1. Inspect Reality (Tech Stack & Foundation)
- **Project Type:** Android App / Xposed Module (`io.github.libxposed.api`, `io.github.libxposed.service`).
- **Language:** Kotlin (primary) and Java.
- **Build System:** Gradle (Kotlin DSL).
- **SDK Versions:** `compileSdk` = 36, `minSdk` = 26, `targetSdk` = 36.
- **UI Framework:** Native Android Views with XML layouts (`res/layout/`). It does **not** use Jetpack Compose.
- **View Binding:** Disabled (`viewBinding = false`). Code uses legacy `findViewById`.
- **Styling & Themes:** Highly custom with hardcoded colors. No robust Android theme system is being used (Manifest declares `@android:style/Theme.DeviceDefault`).
  - Common hardcoded colors: `#F6F8FA` (background), `#24292F` (primary text), `#57606A` (secondary text), `#8C959F` (tertiary text), `#FFFFFF` (card backgrounds).

## 3. UI Architecture Audit
### What pages exist currently?
1. **MainActivity (Home Screen):** The main dashboard for status, control, and diagnostics.
2. **ServiceManagerActivity (Services Screen):** A list screen to manage (enable/disable) individual proxy rule services.

### What does the current Main Screen show?
The Main Screen (`activity_main.xml`) is a `ScrollView` containing a vertical `LinearLayout` with several "Cards":
1. **Header:** Title ("直连代理") and App Logo.
2. **Status Card (模块状态):** Displays Xposed framework connection status (Waiting, Active, Disconnected) along with framework version, API version, and scope.
3. **Control Card (代理控制):** Displays the current VPN status and provides a large primary button to Start/Stop the VPN proxy.
4. **Services Card (服务管理):** Displays summary statistics (Enabled services, Total rules, vIP pool usage) and a button to open the Service Manager.
5. **Tools Card (诊断工具):** Contains a switch to enable Engine Diagnostic Logs, and two buttons for executing "DNS Diagnostics" and "TCP Connectivity Diagnostics".
6. **Output Terminal (输出日志):** A styled text area resembling a console to output the results of the diagnostic tools.
7. **Extra Actions:** Footer buttons linking to a Telegram group and the project's GitHub repository.

### Current UX & Technical UI Issues
1. **Lack of Dark Mode Support:** The app uses hardcoded hex colors (`#F6F8FA`, `#24292F`, `#FFFFFF`) directly in the XML layouts. There is no `values-night` directory or semantic color system (`colors.xml`). The app will not adapt to system dark mode and may become unreadable if dark mode is forced.
2. **Legacy UI Components:** 
   - `ServiceManagerActivity` uses a legacy `ListView` instead of a modern `RecyclerView`.
   - The app uses `findViewById` instead of ViewBinding or Jetpack Compose, making the UI code verbose and prone to null pointer exceptions if layouts change.
3. **Hardcoded Values:** Colors, text sizes (sp), and margins/padding (dp) are extensively hardcoded in the XML files rather than being abstracted into `colors.xml`, `dimens.xml`, and styles.
4. **Layout Hierarchy:** `activity_main.xml` uses deeply nested `LinearLayout`s. This could be flattened using a single `ConstraintLayout` to improve rendering performance.
5. **State Management & Feedback:**
   - Loading states are handled manually (e.g., custom ObjectAnimator on the logo to simulate loading during diagnostics).
   - Button states (e.g., VPN On/Off) manually swap background resources and text colors in the Activity code, rather than using Android `StateListDrawable` selectors or a reactive state flow.
6. **Touch Interaction:** Custom buttons and list items lack standard visual touch feedback (ripple effects), as they use hardcoded shape drawables without `<ripple>` wrappers.
