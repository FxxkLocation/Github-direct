# UI Architecture & Visual System Plan: Github-direct

## 1. Product Context
Based on the audit, the product is a **Multi-service network routing utility**. It is not just a consumer VPN or a GitHub-only tool. It operates as an Xposed module bridging network layers and providing rule-based service routing.

## 2. Information Architecture (IA)

### 2.1 Screen Hierarchy
- **Home (Dashboard)**
  - Connection Status (Xposed module state)
  - Protection Status (VPN state, Start/Stop controls)
  - Enabled Services (Summary stats, quick link to Services)
  - Quick Diagnostics (Network health, engine status)
- **Services (Service Manager)**
  - Search / Filter bar
  - Categories / Grouping of rules
  - List of services with Enable/Disable toggles
- **Diagnostics (Tools & Logs)**
  - VPN connectivity checks
  - DNS resolution tests
  - Rule matching events
  - Recent events / Engine logs (Sanitized for safe exposure)
- **Settings (Configuration)**
  - General (App theme, startup behavior)
  - DNS (Custom DNS, DoH/DoT settings)
  - Network (IPv6, MTU, routing modes)
  - Advanced (Xposed specifics, log levels)
  - About (Version, links)

### 2.2 Navigation
Given the expansion of features into Services, Diagnostics, and Settings, a **Bottom Navigation Bar** is ideal. Since it's a utility, a simple Bottom Navigation with 3-4 tabs (Home, Services, Diagnostics, Settings) provides the most straightforward and functional user experience. Currently, the app uses a simple monolithic Activity structure; transitioning to a single-activity architecture with Fragments or dedicated views for these sections is recommended.

## 3. Visual System Plan

### 3.1 Design Principles
- **Clean & Native:** Adhere to Android Material Design guidelines (Material 3 preferred, but legacy Views friendly).
- **Functional:** Information density should be optimized for a utility app. No unnecessary whitespace, well-structured cards.
- **Low-noise:** Focus on status, metrics, and actionable items.
- **Dark Mode:** Must be a first-class citizen. Hardcoded colors must be entirely removed in favor of semantic references.

### 3.2 Color System & Theme Tokens
We will introduce a semantic color system using `colors.xml` and `values-night/colors.xml`.

**Backgrounds & Surfaces:**
- `colorBackground`: Light: `#F6F8FA`, Dark: `#1C1C1E`
- `colorSurface`: Light: `#FFFFFF`, Dark: `#2C2C2E`
- `colorSurfaceElevated`: Light: `#F0F0F0`, Dark: `#3A3A3C`

**Text & Icons:**
- `textColorPrimary`: Light: `#24292F`, Dark: `#E5E5EA`
- `textColorSecondary`: Light: `#57606A`, Dark: `#8E8E93`
- `textColorTertiary`: Light: `#8C959F`, Dark: `#636366`

**Status Colors (Unified):**
- `colorSuccess`: `#238636` (Connected, Active, Rule Matched)
- `colorWarning`: `#D29922` (Waiting, Reconnecting)
- `colorError`: `#CF222E` (Disconnected, Failed, Blocked)
- `colorInactive`: `#8C959F` (Disabled, Stopped)
- `colorPrimary` / `colorAccent`: `#0969DA` (Primary actions, toggles, links)

### 3.3 Typography & Spacing
- **Typography:** System default (Roboto), mapping standard TextAppearances (Headline, Title, Body, Label).
- **Spacing:** Based on an 8dp grid (4dp, 8dp, 16dp, 24dp, 32dp).
- **Cards:** Standardized `CardView` or rounded background drawables with 12dp corner radius. Subtle elevation in light mode, subtle border/stroke in dark mode.
- **Touch Targets:** Minimum 48dp height for all clickable areas.
- **Feedback:** Ensure all interactable elements have standard Android `<ripple>` effects.

## 4. Components
1. **Status Cards:** Unified layout for displaying system states (Xposed, VPN) with icon, title, subtitle, and a colored status indicator dot.
2. **Action Buttons:** Standardized Primary, Secondary, and Outline buttons with proper state lists (`pressed`, `disabled`).
3. **List Items (Services):** Standardized row component with title, description (optional), icon, and an end-aligned `SwitchCompat`.
4. **Console/Log View:** Monospace text area with auto-scroll and color-coded log levels for the Diagnostics tab.
5. **Toggles/Switches:** System standard `SwitchCompat` styled with `colorPrimary`.

## 5. Expected Files to Change
- **Values & Resources:**
  - `res/values/colors.xml` (Create base semantic colors)
  - `res/values-night/colors.xml` (Create dark mode overrides)
  - `res/values/themes.xml` (Migrate from hardcoded `@android:style/Theme.DeviceDefault` to a structured Material theme, e.g., `Theme.MaterialComponents.DayNight`)
  - `res/values/dimens.xml` (Extract hardcoded dp/sp values)
  - `res/drawable/` (Create `StateListDrawable` and ripple effect backgrounds)
- **Layouts:**
  - `res/layout/activity_main.xml` (Restructure to include Bottom Navigation and Fragment container)
  - `res/layout/activity_service_manager.xml` (Convert legacy `ListView` to `RecyclerView`, potentially move to Fragment)
  - New layouts for Fragments (e.g., `fragment_home.xml`, `fragment_settings.xml`, `fragment_diagnostics.xml`)
- **Code (Kotlin/Java):**
  - `MainActivity.kt` (Implement navigation, replace `findViewById` with ViewBinding if enabled, or restructure UI logic).
  - `ServiceManagerActivity.kt` (Refactor adapter logic, replace `ListView` with `RecyclerView`).
  - Introduction of UI Fragment classes and structured ViewHolders/Adapters.

## 6. Risk Level
- **Medium-High.**
- *Reasoning:* The current app relies heavily on hardcoded UI configurations, deeply nested layouts, and lacks modern architecture components. Refactoring the Information Architecture to include navigation and multiple screens, along with replacing legacy lists with `RecyclerView`, requires significant structural changes. Implementing a true Dark Mode also demands migrating all hardcoded styling to a centralized theme. Careful testing will be crucial to ensure the underlying Xposed logic and VPN controls remain correctly bound to the new UI structure without regressions.
